# Colonies page — clarity prompt (saved)

Saved from the request of 2026-11-22. The prompt below is verbatim. The page it names,
`docs/kit/moddable/colonies.html`, is generated by `docs/kit/build-moddable.py`, so the work it asks
for is applied in `moddable-sections.py` (section intro), `moddable-data-world.py` (per-family
examples) and the renderer — never by editing the generated HTML, which the next build overwrites.

---

**DeepSeek Prompt:**

You are a technical writer specializing in game modding documentation. Your task is to rewrite
`colonies.html` — a modding reference for a space strategy game's colony, economy, and ground war
systems — so that a brand-new modder with no prior knowledge of the codebase can understand it.

**Target audience:** New game modders who will be editing exposed XML/YAML game files. They know
basic HTML/XML syntax but nothing about this game's content pipeline.

**Current problems in the source file:**

1. Many tags are marked as "index entries" with notes like "the guide has not yet documented its
unit, accepted range or failure symptom. Do not infer a bound from the vanilla values." These are
useless to a modder trying to change values.
2. No getting-started section: where do files live, what file extension to use, how to name them,
where to place them.
3. No worked example showing a complete, minimal XML file a modder can copy and modify.
4. Critical warnings (e.g., "capital, outpost, spaceport, terraformer, biosphere are hardcoded by
name — renaming removes behaviour") are buried in the middle of tag lists instead of being
prominent upfront.
5. No explanation of the override/unification system ("XML unifies by file name").
6. No troubleshooting section: what happens if a tag is misspelled, missing, or out of range.
7. No testing workflow: how to verify changes took effect.
8. Terminology like "BID," "UID," "pacing," "fertility," "richness" used without definition.

**Required improvements:**

- Add a "Getting Started" section at the top: file locations, naming conventions, required fields vs
optional fields, how to create a new building/troop/good.
- Add a complete, minimal XML example for each family (Buildings, Troops, Goods, Planet Edicts,
Artifacts, Dyson Rings) that a modder can copy-paste and edit.
- Replace all "index entry / not yet documented" placeholder text with either documented
defaults/ranges or an explicit "safe to leave at vanilla value" note.
- Promote hardcoded-by-name warnings to a prominent "⚠️ Critical" callout box near the top of each
affected family.
- Explain the override/unification system in plain language.
- Add a "Common Mistakes & Troubleshooting" section.
- Add a "How to Test Your Changes" section.
- Define all game-specific terms on first use.
- Keep the existing tag reference tables but make each tag entry include: what it does, valid
range/type, default if omitted, and what breaks if set wrong.
- Preserve the existing HTML structure and CSS classes so the page still renders correctly.

**Output format:** Return the complete rewritten HTML file, ready to save as `colonies.html`. Include
comments marking sections that still need game-engine verification (e.g., tag ranges not yet
confirmed).

---

## Applied as

- Section intro on the generated page: getting started, override rules, critical names, common
  mistakes, testing, glossary.
- Per-family `notation` box with a copyable minimal example for each of the six families.
- Index-only cards still carry generated vanilla values and now say what to do with them; the
  remaining per-field unit/range work is listed in `docs/kit/playtest-moddable-content.md`.
