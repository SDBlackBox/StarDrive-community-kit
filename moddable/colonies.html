Colonies, economy and ground war

What colonies build and what ground units, goods, edicts and relics do.

Where the files go, what they are called, and what is required

A mod is one folder, Mods/<YourMod>/. Put the game's folder tree inside it, with no Content/ step: a building goes to Mods/<YourMod>/Buildings/Civilian/My Building.xml, a troop to Mods/<YourMod>/Troops/My Troop.xml. Every file under the family folder is read, so yours can sit in any subfolder and can be called anything; the Name inside is the id that techs, planets, events, the build list and saves use.

Required and optional. Only Name is mandatory: it is the id. Every other tag can be omitted and the field keeps its default, but the default is not always zero — Unique and Scrappable default to true and a building's Strength to 5. So copy the closest vanilla file rather than writing from a blank page, then change Name, the numbers and the icon. That is also how you add a building, troop or good: copy, rename, retune, and add the new id to whatever should unlock it.

What overrides what. Every file under the family folder is read, whatever it is called. An entry that reuses a vanilla Name replaces that entry; a new Name adds one. The file name is not the join key — Name is, and a tech's unlock list, a planet's building, a troop roster and a save all hold that string or the id it maps to. Renaming Name on an existing building therefore detaches it from the tech that unlocked it.

Critical: 19 building names are read from code

How to test a change

  1. Keep a copy of the vanilla file. Restoring it is the fastest way to prove which change moved the result.
  2. Restart the game. These XML and YAML files are read once at startup, and a running game keeps the values it loaded.
  3. Read the load error before anything else: Failed to parse XML: <relative path> names the file the reader rejected.
  4. Start a new game for anything used at galaxy or colony creation (capital, space port, terrain, artifacts). A save keeps the buildings it already has.
  5. Look at the screen that uses it: the colony build list and a colony's building panel for buildings, the troop list for troops, the trade and freight views for goods, the governor panel for edicts, the empire summary for artifacts.
  6. Change one number at a time. Two changes in one run cannot tell you which one moved the result.

Buildings are the colony's modules: flat and per-colonist bonuses, upkeep, storage and defence. Troops fight on the surface and in boarding, goods move through the freight network, edicts are the governor's presets, and artifacts are permanent empire bonuses. A few buildings are found by name in code, so renaming one removes behaviour the XML never described.

Level 3 — how this section works

A building's Icon is a sprite family, not a path: Buildings/icon_<Icon>_48x48 and _64x64 must both exist. Maintenance is per turn and Cost is one-off; Income and PlusTaxPercentage are credits. Troop Strength is current HP and MaxStrength the cap, with level adding five percent to both attacks and range at level five. Planet edict thresholds are fractions of storage, not absolute amounts. Artifact bonuses stack across the collection and the Spiritual trait multiplies each one.

How these files are laid out — the pattern and its sections

One object per file: the root element <Building> is the entry, and each child element is a field bound by name. An element the class has no field for is dropped without a warning, so a misspelt element is a setting that quietly does nothing.

Root elements in vanilla: <Building> in 115 files.

The keys come in these sections:

  • Identity (13 keys) — What it is and where it shows.
  • Cost and income (5 keys) — What it costs and what it earns.
  • Population, food and terrain (9 keys) — What it does to the colony's growth.
  • Production, research and storage (8 keys) — What it adds to the colony's output.
  • Combat and defence (16 keys) — What it contributes to a fight.
  • Events and modifiers (7 keys) — What it triggers or changes.

Buildings are the colony's modules. Flat and per-colonist bonuses are separate fields, and some buildings are hard-coded by name (capital, outpost, biospheres, spaceport, terraformer).

Identity 13 tags
What it is and where it shows.

Name is the UID used by techs and the colony build list.

Level 3 — the detail

Unique and BuildOnlyOnce are different: one per empire versus one per planet or game.

  • Namestring Building UID and display name.
    It is the join key techs use to unlock the building, and the string the build list and saves carry. A name no tech lists still loads, but the building is never buildable.
    Level 3 — the detail

    Techs unlock a building by this string, and the colony build list and save both key on it, so a rename breaks the unlock unless the tech is renamed with it. The capital, outpost, spaceport, terraformer and biosphere are also found by name in code, so a renamed copy is a new building without their behaviour. The loader reports nothing when the link is missing; the building simply never appears.

    In vanilla: Buildings/Civilian/Biospheres.xml — <Name>Biospheres</Name>; the other 114 files set their own.

  • NameTranslationIndexint GameText id for the building's name.
    `Building.TranslatedName` wraps it, and the build list shows that text.

    Vanilla span: 400 to 18,237 across 115 vanilla values.

    Level 3 — the detail

    The index must match an id in `GameText.yaml`; the loader copies it into every clone of the building. An index with no text shows blank rather than the XML `Name`, because the display path uses the localised string only. `DescriptionIndex` and `ShortDescriptionIndex` are the other two text ids.

    In vanilla: Buildings/Scripted/Crater1.xml — <NameTranslationIndex>4289</NameTranslationIndex>; the other 114 files set their own.

  • DescriptionIndexint GameText id for the building's tooltip.
    `Building.DescriptionText` wraps it in a `LocalizedText`.

    Vanilla span: 401 to 18,238 across 115 vanilla values.

    Level 3 — the detail

    The index is a `GameText.yaml` id, and an id with no text shows an empty tooltip. Nothing validates it at load. `ShortDescriptionIndex` is the one-line version used in lists.

    In vanilla: Buildings/Events/The Underhive Assassins.xml — <DescriptionIndex>17964</DescriptionIndex>; the other 114 files set their own.

  • ShortDescriptionIndexint GameText id for the one-line description.
    `Building.cs` prints it in lists when the index is above zero.

    Vanilla span: 402 to 18,207 across 52 vanilla values.

    Level 3 — the detail

    It is the short form used in the build list and tooltips, while `DescriptionIndex` is the long form. An index of zero means the field is skipped and the list falls back to the name. A wrong id shows blank rather than the XML text.

    In vanilla: Buildings/Scripted/Active Volcano.xml — <ShortDescriptionIndex>4239</ShortDescriptionIndex>; the other 51 files set their own.

  • Iconstring Icon family name.
    Buildings/icon_<Icon>_48x48 and _64x64.
    Level 3 — the detail

    A sprite family name, not a path: the colony screen looks for Buildings/icon_<Icon>_48x48 and _64x64. One missing size shows a placeholder at that zoom rather than failing the building. Reusing another building's Icon is the fastest way to add a variant without new art.

    In vanilla: Buildings/Events/The Underhive Assassins.xml — <Icon>underhive</Icon>; the other 114 files set their own.

  • ShowOnPlanetListbool Shows the building in the planet list.
    `PlanetListScreenItem` adds it to the colony's icon row when the flag is set.
    Level 3 — the detail

    The planet list is the sidebar of colony icons, and this flag decides which buildings get one. It is a display field only: hiding a building from the list does not hide it from the colony screen or the AI. `Category` still controls which build tab lists it.

    In vanilla: Buildings/Events/AI.xml — <ShowOnPlanetList>true</ShowOnPlanetList>; all 46 files set it the same way.

  • Uniquebool Allows only one of the building per planet.
    `SBProduction` refuses a second copy and logs a warning.
    Level 3 — the detail

    The check is `q.Building.Unique && P.BuildingBuilt(q.Building.BID)`, so a duplicate is dropped from the queue with a warning rather than built silently. `BuildOnlyOnce` is the broader build-order restriction. A unique building can still exist on every planet.

    In vanilla: Buildings/Civilian/Biospheres.xml — 1 entry: false; Buildings/Civilian/Terraformer.xml — 1 entry: false.

  • BuildOnlyOncebool Restricts the building to a single build order.
    `Building.IsSuitableForBlueprints` excludes it from plans, and `Empire` consults the existing buildings before ordering it.
    Level 3 — the detail

    `IsSuitableForBlueprints` returns false for a build-once building, so blueprints never place it. `Empire.cs` also checks the planet's buildings before it hands the order out. The per-planet duplicate limit is `Unique`; this flag is the stricter, empire-facing version.

    In vanilla: Buildings/Events/The Underhive Assassins.xml — <BuildOnlyOnce>true</BuildOnlyOnce>; all 6 files set it the same way.

  • Scrappablebool Whether the building can be scrapped.
    `Building.IsSuitableForBlueprints` requires it, and the defence picker only scraps buildings that have it.
    Level 3 — the detail

    `Planet_BuildDefenses` looks for the weakest military building that is also `Scrappable`, so a protected building is never removed for a new one. Blueprints also skip a non-scrappable building. The default is true, so the tag is written only to protect something.

    In vanilla: Buildings/Civilian/Capital City.xml — <Scrappable>false</Scrappable>; the other 63 files set their own.

  • CanBuildAnywherebool Lets the building ignore tile restrictions.
    `Building.cs` uses it when it places an event building and when it searches for a valid tile.
    Level 3 — the detail

    The flag appears twice in `Building.cs`: once to stop an event building forcing a random habitable tile (line 414), and once in the tile filter at line 426, where an ordinary building needs `NoBuildingOnTile`. A building with it can sit on any free tile, which is how crash sites and event structures land anywhere.

    In vanilla: Buildings/Civilian/Biospheres.xml — <CanBuildAnywhere>true</CanBuildAnywhere>; the other 52 files set their own.

  • NoRandomSpawnbool Keeps the building out of the random event pool.
    `SolarSystemBody` filters event buildings with `EventHere && !NoRandomSpawn`.
    Level 3 — the detail

    That filter decides which buildings can be placed as a random ruin on a generated tile. Setting it means the building appears only when an event or a file names it. `EventSpawnChance` is the frequency for the ones that stay in the pool.

    In vanilla: Buildings/Events/Ancient megacity.xml — <NoRandomSpawn>true</NoRandomSpawn>; all 14 files set it the same way.

  • WinsGamebool Marks the building as a victory condition.
    `Planet_ConstructionQueue` sets `HasWinBuilding` when it is true.
    Level 3 — the detail

    One building with this flag on any of an empire's planets is enough to set the win flag, so a mod can make a hidden structure the objective. The check runs when the queue finishes the building, not continuously. It is the only building field the victory code reads.

    In vanilla: Buildings/Remnant tree/Ascension Array.xml — 1 entry: true.

  • Categoryenum The palette group the building is listed under.
    The type is `BuildingCategory`, and the colony build list groups and sorts by it.
    Level 3 — the detail

    `BuildingCategory` is a fixed enum, so a value outside it becomes the default. The label does not change behaviour; it decides which tab lists the building and which filter the AI uses when it looks for a kind of building. `Technology` classifies buildings from their numbers, not from this field.

What it costs and what it earns.

Level 3 — the detail

Income and PlusTaxPercentage are credits; a negative Income is a cost.

  • Costfloat Production cost of the building before pace scaling.
    `Building.ActualCost` multiplies it by `ProductionPace`, and the colony build list and research popup show that result.

    Vanilla span: 0 to 15,000 across 93 vanilla values.

    Level 3 — the detail

    `ActualCost(e)` is `Cost * e.Universe.ProductionPace`, so the file's number is the cost at pace 1. The build list, the deep-space building window and the research popup all display the scaled figure. Maintenance is a separate field and does not follow the cost.

    In vanilla: Buildings/Events/Abandoned Mine.xml — <Cost>40</Cost>; the other 92 files set their own.

  • Maintenancefloat Credits per turn the building costs.
    `Building.GetMaintenanceCost` scales it by the empire's civilian maintenance modifier.

    Vanilla span: 0 to 4 across 85 vanilla values.

    Level 3 — the detail

    The deep-space building window prints the scaled figure, and the colony upkeep total adds it. `CivMaintMod` on the empire multiplies it, which is why a tech that reduces civilian maintenance changes the number without touching the file. It is a cost, so the colony budget subtracts it.

    In vanilla: Buildings/Civilian/Capital City.xml — <Maintenance>0</Maintenance>; the other 84 files set their own.

  • Incomefloat Flat credits per turn from the building.
    `Building.IsMoneyBuilding` counts it, and the colony income code adds it when it is above zero.

    Vanilla span: 0.5 to 8 across 4 vanilla values.

    Level 3 — the detail

    Unlike `CreditsPerColonist`, this is a flat sum that does not scale with population. `IsMoneyBuilding` treats it as a money building for tech classification and the colony summary. It is gross income, with `Maintenance` subtracted separately.

    In vanilla: Buildings/Civilian/Customs Station.xml — <Income>0.5</Income>; the other 3 files set their own.

  • PlusTaxPercentagefloat Tax rate the building adds.
    `Building.IsMoneyBuilding` counts it, and the colony tax calculation adds it to the rate.

    Vanilla span: 0.2 to 0.6 across 5 vanilla values.

    Level 3 — the detail

    It is a percentage contribution to the colony's tax rate, not credits, so its effect depends on the population and goods being taxed. `CreditsPerColonist` and `Income` are the direct money fields. A negative value lowers the rate.

    In vanilla: Buildings/Civilian/Capital City.xml — <PlusTaxPercentage>.40</PlusTaxPercentage>; the other 4 files set their own.

  • CreditsPerColonistfloat Credits per colonist per turn.
    `Building.IsMoneyBuilding` is true when it is positive, and the colony income calculation adds it.

    Vanilla span: -0.15 to 1.6 across 9 vanilla values.

    Level 3 — the detail

    It is a per-colonist rate, so its value grows with the planet's population rather than sitting flat. `IsMoneyBuilding` uses it for tech classification and the colony summary. A planet with no colonists gets nothing from it.

    In vanilla: Buildings/Civilian/Capital City.xml — <CreditsPerColonist>1</CreditsPerColonist>; the other 8 files set their own.

What it does to the colony's growth.

Flat and per-colonist bonuses stack with fertility.

Level 3 — the detail

    `Building.ProducesPopulation` and the population-relevance check at line 398 use it.

    Vanilla span: -1,100 to 3,000 across 14 vanilla values.

    Level 3 — the detail

    It raises the planet's population cap, so its effect only appears once the colony fills the old one. A zero value makes the building not population-relevant, which is what the tech classification tests. It does not change the growth rate.

    In vanilla: Buildings/Events/Forcefield.xml — <MaxPopIncrease>-700</MaxPopIncrease>; the other 13 files set their own.

    `Building.ProducesPopulation` is true when it is positive.

    In vanilla: Buildings/Civilian/Cloning Center.xml — <PlusFlatPopulation>7</PlusFlatPopulation>; the other 4 files set their own.

    In vanilla: Buildings/Food/Aeroponic Farm.xml — <PlusFoodPerColonist>0.2</PlusFoodPerColonist>; the other 3 files set their own.

  • FoodCachefloat Food storage the building adds.
    `IsBadCacheResourceBuilding` warns when a cache exists without any food production on the same building.

    Vanilla span: 250 to 4,000 across 3 vanilla values.

    Level 3 — the detail

    The field is storage, so it raises the planet's buffer rather than its output. `Building.cs` warns when `FoodCache > 0` and both `PlusFlatFoodAmount` and `PlusFoodPerColonist` are zero, which catches a cache with nothing to cache. The warning fires during generation, in `SolarSystemBody`, not at load.

    In vanilla: Buildings/Events/Avar.xml — 1 entry: 3100; Buildings/Events/ExoticFruits.xml — 1 entry: 250; Buildings/Events/Oasis.xml — 1 entry: 4000.

  • MaxFertilityOnBuildfloat Fertility ceiling the building adds to its tile.
    `MaxFertilityOnBuildFor` multiplies it by the empire's racial environment modifier for the planet's category.

    Vanilla span: -0.65 to 0.6 across 17 vanilla values.

    Level 3 — the detail

    The per-empire helper is what the colony screen and the blueprint screen call, so the same building is worth different amounts to different races. It is a ceiling rather than a flat addition, so a tile already at that fertility gains nothing. `PlusTerraformPoints` is the other way buildings change fertility.

    In vanilla: Buildings/Civilian/HDZone.xml — <MaxFertilityOnBuild>-0.2</MaxFertilityOnBuild>; the other 16 files set their own.

  • CanBeTerraformedbool Lets the building's tile be terraformed.
    `PlanetGridSquare.TerrainCanBeTerraformed` requires it, and `Planet.HasTerrainToTerraform` looks for it across the planet.
    Level 3 — the detail

    The predicate is `BuildingOnTile && Building.CanBeTerraformed`, so only a building that sets the flag has its tile improved. `HasTerrainToTerraform` is the same check over every tile, and the terraforming tech uses it to decide whether the investment buys anything. A building without it protects its tile.

    In vanilla: Buildings/Scripted/Active Volcano.xml — <CanBeTerraformed>true</CanBeTerraformed>; all 4 files set it the same way.

  • CanBeCreatedFromLavabool Lets the building appear when lava on a tile solidifies.
    `Volcano` filters the buildings it may create with this flag.
    Level 3 — the detail

    `Volcano.cs` builds its candidate list from `ResourceManager.BuildingsDict` filtered on `CanBeCreatedFromLava`, so a building without it can never replace cooling lava. `ImmueToLava` is the other half, protecting an existing building from the eruption. Both are read only when a tile changes.

    In vanilla: Buildings/Events/Exotic Minerals.xml — 1 entry: true; Buildings/Events/GoldDeposit.xml — 1 entry: true; Buildings/Events/Rocks.xml — 1 entry: true.

  • ImmueToLavabool Protects the building from lava destroying its tile.
    `PlanetGridSquare.ImmuneToLava` returns true when the building sets it.
    Level 3 — the detail

    The field is misspelled in the code (`ImmueToLava`), so the correct spelling in a file is dropped. A protected building survives an eruption that would otherwise clear the tile. `CanBeCreatedFromLava` is the other half, controlling what appears after lava cools.

    In vanilla: Buildings/Scripted/Active Volcano.xml — <ImmueToLava>true</ImmueToLava>; all 8 files set it the same way.
