General game options

The values every empire starts from: opponents, the turn clock, trait points, upkeep, repair, research and the AI's budgets.

families: 4files: 4 tags: 99generated from: ef406fa04

These are the files a total conversion edits first, because one key changes every empire at once without touching a ship or a building. Most of them are multipliers applied after the per-item value, so a 2 doubles a whole category; a few are absolute starting numbers that only matter when a galaxy is generated. The AI files are read per race, keyed by portrait, and they replace vanilla rather than merging key by key.

Level 3 — how this section works

Globals.yaml is matched by key to GamePlayGlobals; an unknown key is ignored with no warning, so a typo looks like a value that did nothing. Per-item prices live in the content files, and the globals scale them afterwards, which is why ShipMaintenance Multiplier is a stronger lever than editing 200 modules. Starting values such as TurnTimer, TraitPoints and the opponent count are baked into a save when it is created: test them in a new game, not an old one. Two flags, EnableSalvageOps and EnableHullPlates, are forced off for a mod before its own values are read, so a mod that wants them must turn them on itself.

Order of operations for a price: the module, weapon or building file gives the base number, the empire's racial traits apply their modifier, then the global multiplier from this section applies. A save keeps the globals it was created with.

GlobalsTier 11 file
The game's master switchboard: one file of numbers and on/off flags that every empire, ship and colony reads.

YAML · GamePlayGlobals.Deserialize (YamlParser)

A mod does not replace this file, it extends it: unset keys keep the vanilla value. That makes it the safest first mod, and the easiest place to change the feel of a whole game.

Level 3 — the detail

Fields are matched by name to GamePlayGlobals. Two are forced off for every mod before the mod's own values are read: EnableSalvageOps and EnableHullPlates, because they depend on content a mod may not have. Unknown keys are ignored.

Override: One file. A mod's Globals.yaml inherits every vanilla value, then overrides the keys it names.

Start and galaxy 8 tags
The shape of a new game.

Set these before generating a galaxy; a saved game keeps what it was created with.

Level 3 — the detail

Opponent counts, turn clock, trait points and the expansion pressure the AI feels.

  • MaxOpponentsint How many opponents the setup screen offers at most.
    It caps the opponent button, which cycles from 1 to this value, and a corners game ignores it and uses 3. It is a new-game setting, so a save keeps the opponents it was created with.

    Allowed range: no loader bound; the setup screen uses 1 to this value in a standard game and 3 in a corners game. Math: the button cycles 1..value; 7 = seven opponents, 1 = a duel, 0 or less collapses to 1.

    Level 3 — the detail

The loader does not clamp it, and a negative value behaves like 0 rather than producing an error. The setup screen is the only reader, so editing it changes nothing once a galaxy exists.

Economy and construction 11 tags
What things cost and how fast they are built.

These multiply or add to the prices the content files already carry.

Level 3 — the detail

    Level 3 — the detail

The gate applies after racial MaintMod and before the budget screen totals, so two races with the same ships still pay differently. It is read when a save loads; an old save keeps the multiplier it was created with.

Repair 6 tags
How ships heal.

Colony repair is per second; module self-repair is a separate rate.

Level 3 — the detail

Both are multiplied by the module's own repair fields before these globals.

  • BaseShipyardRepairfloat Repair per second from planetary ship repair buildings.
    It converts a world's summed ShipRepair into repair per second, so vanilla's 10 turns 5 points of repair into 50 per second. Every colony multiplier then scales that base.
    Level 3 — the detail

    The buildings' ShipRepair values are summed with the world's own repair, then multiplied by this, the colony level and the in-combat modifier. A separate path uses the same value for building repair, so raising it speeds both. The code default is 100 but Globals.yaml sets 10, and the file wins.

    In vanilla: Globals.yaml — 1 entry: 10.0.

  • BonusRepairPerColonyLevelfloat How much a colony's level adds to the ship repair it gives.
    Planet repair is the world's repair buildings times this value times its level, so vanilla 0.1 gives a level-1 world 10% and a level-5 world 50% of the base. Zero switches orbital repair off at every level.
    Level 3 — the detail

    The level used is the colony's own and never falls below 1, so colonisation alone cannot make the multiplier zero. It is applied inside the per-second planet repair rate, after the building totals and before the in-combat modifier. The same multiplier is used wherever colony repair is computed, so a zero drains the planet repair service, not just the shipyard.

    Level 3 — the detail

Derelicts and salvage 7 tags
What is left after a ship dies, and what can be stripped from it.

The caps are multiples of the galaxy's star systems, clamped to 0.1-10 with a log warning.

Level 3 — the detail

Salvage ops must be on for drifting and salvageable derelicts to exist at all; mods start with it off.

  • DerelictChancefloat What share of eligible ship deaths leave a derelict.
    It is the base percent for corvette-and-above warships and untethered stations, and the chance then falls as the galaxy fills toward the drifting or salvageable cap. At 0 no derelicts are created.
    Level 3 — the detail

    The roll happens when the ship dies and before the cap is applied, so a full cap turns a success into a normal explosion. With salvage ops on the cap counts salvageable wrecks and the rest drift; with them off it counts drifting ones only. The value is read per death, not stored in the save.

    Level 3 — the detail

    It counts every drifting derelict, seen or not, and past the cap a new drifting death replaces the oldest unseen one or becomes a normal explosion. Below 1 the galaxy holds fewer than one per system. The value is read when a derelict is created, not stored per wreck.

Combat modifiers 7 tags
Global multipliers on fighting.

Applied on top of module and weapon values.

Level 3 — the detail

These are the cheapest way to shift combat pacing without editing 300 files.

  • ShipDestroyThresholdfloat How much internal module damage a ship can take before it dies.
    It is a share of the ship's internal-slot health, not its total hit points, and it also pulls each role's retreat threshold toward it. A higher value makes ships die and retreat earlier.

    Allowed range: no loader bound; the comparison expects a 0..1 share. Math: a ship dies when internal health share < value; 0 = only at zero, 0.5 = vanilla, 1 = any internal damage.

    Level 3 — the detail

    `InternalSlotsHealthPercent < ShipDestroyThreshold` kills the ship in `Ship_Events`, and `ShipResupply` blends a role's own threshold toward this value, so one number changes both death and when a ship leaves a fight. Vanilla 0.5 means a ship dies once half its internal health is gone; 0 keeps it fighting until the last internal module, and 1 kills it as soon as any internal damage lands. The loader does not clamp it, so a value outside 0..1 makes the comparison meaningless rather than producing an error. It is read from the globals whenever the checks run, not stored per ship.

  • ShieldPowerMultiplierfloat Multiplies every empire's shield power after its racial modifier.
    It scales the empire's ShieldPowerMod, so 1 is neutral and 2 doubles the shields on every ship that empire builds. It does not change shield regeneration or module storage, which keep their own numbers.

    Allowed range: no loader bound. Math: shield strength = module shields × (1 + empire ShieldPowerMod) × value; 0.5 = half, 1 = vanilla, 2 = double.

The [0, 6] notation, number by number

Fighters: [0, 6] is a YAML list of two numbers on one line. The game reads the first number as the low end and the second as the high end of a ship count; it never reads the brackets and the comma as one value.

itemwhat it iswhat it does
[ ]listMarks the two numbers as one list. The comma separates them; the space after it is optional.
0low endThe count used when randomized fleet sizes are off, and the smallest result when they are on. It is a whole number of ships, not a percentage and not a share of a budget.
6high endThe upper bound when randomized sizes are on. It is exclusive: the roll is [0, 6) and the result is truncated to a whole number, so the highest count produced is 5. With randomization off this number is ignored entirely.
