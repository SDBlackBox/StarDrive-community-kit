Races, diplomacy and events

Who the empires are, what they are like and what they say: race templates, traits, personalities, encounters and events.

families: 6files: 152 tags: 258generated from: ef406fa04

A race file is also the empire's startup template: every Default*, Pirate* and Remnant* line is a ship-design name, so changing one changes what that empire starts with and what its governors build. Traits are chosen at game start and add their modifiers to the empire. Diplomacy personalities set starting relations and how fast they drift, while dialog pools only choose the words. Encounters are looked up by faction and step, and exploration events by their own name.

Level 3 — how this section works

A missing design name falls back to a default, often a vanilla one, so a typo looks like the AI ignoring your ship rather than an error. Trait Excludes is a name and trait points come from Globals.TraitPoints. An encounter is selected by Faction plus Step, and the first loaded match wins, so two files with the same pair shadow each other. Event outcomes are weighted by Chance and can spawn ships, grant a tech or edit the planet. A missing dialog pool falls back to Default and never blocks the treaty.

  • Namestring The empire's name and its id: the exact string every other reference uses to find it.
    Other files reach an empire by this text: `AbsorbedBy`, `RebelName`, an encounter's `Faction` and the espionage messages all resolve it through `GetEmpireByName`, which compares the string exactly. It is also what the player reads everywhere, from the diplomacy header to the colony list, so it is both a label and a join key.

    Allowed range: free text, but it doubles as an id: keep it unique and change every string that names this empire with it. Vanilla uses full titles, e.g. `The United Federation`, `Cordrazine Collective`, `The Remnant`, `Corsairs` and `Unknown`.

    Level 3 — the detail

    `AddEmpire` special-cases four values — `Cordrazine Collective`, `The Remnant`, `Unknown` and `Corsairs` — by setting `Universe.Cordrazine`, `Remnants`, `Unknown` and `Corsairs`, which the remnant storyline, portals and pirate spawning read, so renaming one of those races leaves the game running with that content quietly off. `AbsorbedBy` and rebellion creation compare the string against other empires' names, so a duplicate makes the second empire unresolvable. The save stores it as the player name and the difficulty and score screens print it, so it is the empire's whole identity rather than a display field. There is no localisation id behind it, so a translation must override the race file.

    In vanilla: Races/Cordrazine.xml — <Name>Cordrazine Collective</Name>; the other 12 files set their own.

  • Singularstring One member of the race, used wherever a sentence talks about a single person.
    It fills the `SING` token in story encounters, is the subject of the race-description paragraphs, labels the owner column in the planet and exotic-system lists, and appears in invasion alerts such as 'Human troops are landing'. It also becomes the race's `ShipType` when that field is left empty, so it decides the default hull family.
    Level 3 — the detail

    `EncounterInstance.FormatText` replaces `SING` with it, `SolarSystemBody.OwnerName` and `PlanetListScreenItem` print it, and `ResourceManager` copies it into `ShipType` when that field is blank. The race setup screen searches for the race whose `Singular` is exactly `Human` to choose its default selection, so renaming that value silently opens setup on the first major race instead. Empty text is accepted and produces blank subjects plus an empty `ShipType`, which then warns at load and strips that race's hull and dialogue keys. It is stored in the save, so a change reaches new games only.

    In vanilla: Races/Cordrazine.xml — <Singular>Cordrazine</Singular>; the other 12 files set their own.

  • Pluralstring Many members of the race, used where the sentence treats them as a people.
    The race-description builder inserts it before phrases like 'are natural sailors', the budget screen lists trade partners by it, and the espionage screen names the target people with it. Rebel factions replace it with `RebelPlur`, so a rebellion does not inherit the parent's name.
    Level 3 — the detail

    `RaceDesignScreen_RaceDescription` calls `.Plural(...)` on the generated paragraphs, which makes this the word the setup screen repeats most. `BudgetScreen` prints it in the trade list and `AgentListItem` in the espionage target list, while notifications use `Singular` instead, which is why both fields are needed. `CreateRebelsFromEmpireData` overwrites it with `RebelPlur` and `Singular` with `RebelSing` at rebellion time. There is no fallback and no localisation id, so an empty value leaves a gap in every one of those sentences.

    In vanilla: Races/Cordrazine.xml — <Plural>Cordrazine</Plural>; the other 12 files set their own.

  • Adj1string An adjective for the race, substituted into story text.
    Only the encounter formatter reads it: an `ADJ1` token in an event's text becomes this word. The race setup screen passes the value through unchanged and offers no field to edit it, so a custom race keeps the adjective of the file it was based on.
    Level 3 — the detail

    `EncounterInstance.FormatText` handles the `ADJ1` and `ADJ2` tokens and no other code reads either field. Vanilla sets `strange` in three race files and leaves the rest empty. The word is inserted as written with no capitalisation fix, so an event that opens a sentence with the token needs a capitalised value. An empty value substitutes nothing and leaves the event's sentence short rather than failing.

    In vanilla: Races/Cordrazine.xml — <Adj1>strange</Adj1>; the other 7 files set their own.

  • Adj2string A second adjective for the race, used by the same event text as `Adj1`.
    The encounter formatter substitutes it for an `ADJ2` token. Like `Adj1` it has no screen of its own and does not appear in the race description, so it only shows up where a hand-written event asks for it.
    Level 3 — the detail

    `EncounterInstance.FormatText` is the only reader, through the `ADJ2` case next to `ADJ1`. Vanilla sets `eerie` in the same three race files that set `strange`.   • HomeworldNamestring The name of the race's home planet, as shown in text.
    It is a label, not a rename: the starting planet keeps whatever name its solar system file gives it, and this string is what the interface calls that world. It appears in the diplomacy intel line, the closing sentence of the race description and the espionage dossier's home-planet field.
    Level 3 — the detail

    `MainDiplomacyScreen` prints it under the Homeworld heading and `RaceDesignScreen_RaceDescription` ends with 'The <Singular> homeworld of <value>'. `DossierPanel` copies it into the agent's `HomePlanet` label, which is the only place espionage shows it. Galaxy generation never reads it, so changing it on an existing race changes text and nothing else, and a value that disagrees with the planet's real name is not an error.     In vanilla: Races/Corsairs.xml — <HomeworldName>Earth</HomeworldName>; the other 12 files set their own.

  • HomeSystemNamestring The file stem of the solar system where the empire starts.
    Galaxy generation loads `SolarSystems/<value>.xml` for the empire's starting system, and that file supplies the homeworld the race begins on. If no file matches, the game generates a random system under the same name instead, so a typo costs the hand-built layout but not the start.
    Level 3 — the detail

    `CreateSystemPlaceHolders` calls `LoadSolarSystemData(HomeSystemName)` and keeps a null when the file is missing. `GenerateSystems` then takes the null branch and calls `GenerateRandomSystem` with the same name, while a non-null result goes through `GenerateFromData` and uses the file's planets, resources and placement. Several vanilla races share `Sol`, and two races naming the same system each get their own copy of its layout rather than sharing one. The field is read only when a galaxy is created, so a save keeps the system it was generated with.

    In vanilla: Races/Corsairs.xml — <HomeSystemName>Sol</HomeSystemName>; the other 12 files set their own.

  • PortraitNamestring The race's portrait id and the key its per-race AI settings are filed under.
    The game loads `Portraits/<value>` for the race's picture in diplomacy, espionage, the governor panel and the relations diagram, and uses the same string to find the race's block in `Research.yaml` and `Budgets.yaml`. It also names the Markov name file that labels planets in that empire's new systems.
    Level 3 — the detail

    `ResourceManager.Texture("Portraits/" + PortraitName)` draws the picture everywhere it appears, and a missing texture logs and falls back to the red `NewUI/x_red` placeholder rather than failing. `ResearchOptions` matches its per-race block on this string or `All`, while `BudgetPriorities` reads only the `All` block and warns that every other block is ignored. `GetRandomNames` builds the path `NameGenerators/spynames_<value>.txt` and returns no generator when that file is absent, so planet naming in new systems quietly loses its custom names. `FindRebellion` compares this value against a rebel name, so two races sharing a value are treated as the same rebellion, which is why the three faction files reuse `unknown`. Vanilla uses the short name here even when `Name` is a full title (`Human`, not `The United Federation`).

    In vanilla: Races/Corsairs.xml — <PortraitName>unknown</PortraitName>; the other 12 files set their own.

  • FlagIndexint Zero-based index of the sprite in the `Flags` atlas that marks this empire.
    The flag is drawn on diplomacy cards, the relations diagram, colony and mining overlays, event popups and the espionage list, tinted with the empire colour. `0` is the first flag in the atlas, not 'no flag'; only a save header uses `-1` to mean that.

    Allowed range: 0 to the flag count minus one; the setup screen clamps to that, a race file is not clamped. Vanilla runs from 3 (Human) to 64 (Corsairs and Unknown), and the count follows the `Flags` atlas.

  • ShipTypestring The race's ship-style id: the string that ties it to hulls, tech unlocks and its own text and name files.
    Hulls carry a matching `Style`, and a tech's `<HullsUnlocked><ShipType>` applies only when it is empty, `ALL`, or this value, so the same tree gives each people a different hull list. The same string also picks the race's diplomacy lines, spy-name file, vanity-name pool and role labels, and the setup screen uses it to find the race's archetype.

    Allowed range: any string, but it must match the `Style` of the hulls you want and the keys already used by the dialogue, spy-name and ship-name files. Vanilla has 13 values: Terran for Human, plus Cordrazine, Pollops, Opteris, Draylok, Kulrathi, Vulfen, Ralyeh, Revoran, Draug, Corsair, Remnant and Unknown.

    Level 3 — the detail

    `WeCanBuildThis` refuses a design until its hull is in `UnlockedHullsDict`, which `TechEntry.UnLockHulls` fills only from tech entries whose `<ShipType>` passes `IsTypeUnlockableBy` — empty, `ALL`, or this value — so this is the field that makes a hull tech racial. The restriction is not permanent ownership: `CheckSource` also accepts a tech stolen from or conquered from that people, and `ShipStyleMatch` keeps an absorbed empire's styles buildable, which is how a race can end up flying another people's hulls. The same string drives UI and spawns: the design browser sorts the race's own style first, the race setup preview picks its largest cruiser, and scenario and faction spawns filter hulls by it. It also keys text and names — `Opinion_Positive_/Neutral_/Negative_<ShipType>` in the diplomacy file, `spynames_<ShipType>.txt` for agents (falling back to Humans), vanity names in `ShipNames/ShipNames.xml`, and race-specific role labels in `ShipRoles`. An empty value is replaced at load by the race's `Singular` with only a warning, after which its hull entries, dialogue keys and name files no longer match; a wrong value silently gives a race with a thinner hull list and blank opinion lines.

    In vanilla: Races/Cordrazine.xml — <ShipType>Cordrazine</ShipType>; the other 12 files set their own.

Growth 6 tags
How fast a colony grows and what it eats.

The six fields are separate: two set growth bounds, one scales the result, one sets the food charge, and two shape the homeworld.

Level 3 — the detail

Population is held in thousandths of a billion, so 0.005 is 5 million people per turn.

  • ConsumptionModifierfloat Scales how much food each billion colonists eats per turn.
    The game charges 1 food per billion colonists per turn before this field, and the value is added to that 1, so -0.15 charges 0.85 and 0.1 charges 1.1. Cybernetic races pay the same charge in production instead of food. It applies to every colony, and to the food that troops in space consume, not only the homeworld.

    Allowed range: the loader sets no bounds; -1 is the lowest sensible value because 1 + value reaches 0, and below -1 the charge turns negative. Math: consumption = 1 + value, per billion colonists per turn; -1 = 0, -0.15 = 0.85, 0 = 1, 0.1 = 1.1, 0.5 = 1.5.

    Level 3 — the detail

    `ConsumptionPerColonist = 1 + ConsumptionModifier` is multiplied by population in billions, so -0.15 saves 0.15 food per billion people per turn and 0.1 adds the same. Vanilla Efficient Metabolism sets -0.15 for 3 points and Gluttonous sets 0.1 and refunds 2. The code applies no clamp: at -1 a colony eats nothing, and below -1 the charge is negative, so keep the value above -1. The tech bonus Consumption Bonus subtracts its value from this field, which is why a positive tech bonus makes food cheaper.

    In vanilla: RacialTraits/RacialTraits.xml, one value per trait option — Efficient Metabolism -0.15 = 0.85 food per billion colonists, Gluttonous 0.1 = 1.1 food per billion colonists.

  • PopGrowthMinfloat Sets a floor on how many people a colony gains each turn.
    Growth is computed from population, spare capacity and the empire's base reproductive rate, and this field raises the result to a minimum. The unit is billions per turn, so 0.005 means at least 5 million people per turn. The floor is applied after the growth ceiling and before ReproductionMod, and it is skipped while a colony is starving, over capacity or in recent combat. Vanilla Fertile sets 0.005.

    Allowed range: the loader sets no bounds; the colony is clamped to 0..MaxPopulation and then to at least 10 people, so a negative floor can shrink a colony but not empty it. Math: floor = value × 1000 people per turn; -0.005 = -5 million, 0 = no floor, 0.005 = 5 million, 0.05 = 50 million.

    Level 3 — the detail

    `repRate = repRate.LowerBound(PopGrowthMin * 1000)` runs on the internal scale where 1000 is one billion, so 0.005 is a floor of 5 units, or 5 million people, per turn. On a small or crowded colony the floor can supply most of the growth, which is why Fertile matters most early. Because the floor applies even when natural growth is negative, a positive value can keep a shrinking colony from emptying. Vanilla uses it only on Fertile, at 0.005 for 2 points.

    In vanilla: RacialTraits/RacialTraits.xml, one value on one trait option — Fertile 0.005 = at least 5 million people per turn, for 2 points.

  • PopGrowthMaxfloat Caps how many people a colony can gain in one turn.
    The cap is checked before the floor and before ReproductionMod, and 0 disables it, so an unset field does not mean no growth. The unit is billions per turn: 0.015 caps growth at 15 million people per turn. It bites hardest on large, fertile worlds where natural growth is high, and it affects every colony including the homeworld. Vanilla Less Fertile sets 0.015.

    Allowed range: the loader sets no bounds; 0 turns the cap off and a negative cap forces population loss. Math: cap = value × 1000 people per turn; -0.005 = at most -5 million, 0 = no cap, 0.015 = at most 15 million, 0.05 = at most 50 million.

    Level 3 — the detail

    `if (PopGrowthMax.NotZero()) repRate = repRate.UpperBound(PopGrowthMax * 1000)` caps the per-turn gain at 0.015 billion, or 15 million people, on the internal scale. It is a ceiling rather than a multiplier, so a world below it grows exactly as it would without the trait. Vanilla Less Fertile sets 0.015 and refunds 3 points, and no other trait sets it. A value of 0 skips the cap entirely, so use a small positive number to slow growth.

    In vanilla: RacialTraits/RacialTraits.xml, one value on one trait option — Less Fertile 0.015 = at most 15 million people per turn, for -3 points (a refund of 3).

  • ReproductionModfloat Multiplies a colony's population growth after the floor and ceiling are applied.
    The value is a fraction added to the growth rate rather than a flat number of people: 0.5 makes growth half again as fast and -0.5 halves it. It stacks with the growth floor and ceiling and applies to every colony. It is separate from PopGrowthMin and PopGrowthMax, which set the bounds this multiplier then scales. No vanilla racial trait sets it, so it is free design space.

    Allowed range: the loader sets no bounds; -1 zeroes growth and below -1 reverses it. Math: growth = base × (1 + value); -1 = 0%, -0.5 = 50%, 0 = 100%, 0.5 = 150%, 1 = 200%.

    Level 3 — the detail

    `repRate += repRate * ReproductionMod` runs after the floor and ceiling, so 0.5 turns a 10-million gain into 15 million and -0.5 turns it into 5 million. The vanilla artifact set uses the same field: the first artifact in `Artifacts/MainArtifacts.xml` grants 0.5. A value of -1 stops all natural growth, and below -1 growth turns negative; the loader does not clamp it. Because it is multiplicative, it cannot lift a colony that is already at its population maximum.

    In vanilla: no racial trait sets it; Artifacts/MainArtifacts.xml sets 0.5 = 150% growth on the first artifact.

  • HomeworldFertModfloat Raises or lowers the fertility of the empire's starting homeworld when a galaxy is generated.
    The homeworld's maximum fertility is built from a base of 2 plus this value, then divided by the race's environment modifier for that planet category. -0.35 gives 1.65 and -1.0 gives 1.0, half the neutral base. It is applied once at galaxy creation and only to the starting homeworld, so captured and later-settled worlds are unaffected. Vanilla Polluted Homeworld uses -0.35 and Industrialized Homeworld uses -1.0.

    Allowed range: the loader and the generator set no bounds. Math: fertility = (2 + value) / the race's environment modifier for that planet category; at a neutral modifier of 1: -2 = 0, -1 = 1, -0.35 = 1.65, 0 = 2, 1 = 3.

    Level 3 — the detail

    `baseMaxFertility = (2 + HomeworldFertMod) / PreferredEnvModifier` runs in `CreateHomeWorldFertilityAndRichness`, once per homeworld, before buildings add their own fertility. -0.35 (Polluted Homeworld, -2 points) gives 1.65 against the neutral 2.0, and -1.0 (Industrialized Homeworld, 2 points) gives 1.0. Because it is read only when the galaxy is generated, it does nothing in an existing save and nothing on a world settled later.

    In vanilla: RacialTraits/RacialTraits.xml, two values on two trait options — Polluted Homeworld -0.35 = 1.65 fertility, Industrialized Homeworld -1.0 = 1.0 fertility.

  • HomeworldRichModfloat Raises or lowers the mineral richness of the empire's starting homeworld.
    The homeworld starts at a mineral richness of 1 before this value is added, so 1.0 doubles it and -0.5 halves it. Richness multiplies the production a colony gets from its tiles, which makes this a long-term economic trait. Like fertility, it is applied once at galaxy generation and only to the starting homeworld. Vanilla Industrialized Homeworld sets 1.0.

    Allowed range: galaxy generation sets no bounds; later richness changes are floored at 0. Math: richness = 1 + value; -1 = 0, -0.5 = 0.5, 0 = 1, 0.5 = 1.5, 1 = 2, 2 = 3.

    Level 3 — the detail

    `MineralRichness = 1f + HomeworldRichMod` is set in the same generation pass as fertility, before buildings or technology change production. 1.0, the Industrialized Homeworld value, doubles the homeworld's tile production for the rest of the game. The field is read only when the galaxy is created, so a save keeps the richness it was generated with and other colonies ignore it.

    In vanilla: RacialTraits/RacialTraits.xml, one value on one trait option — Industrialized Homeworld 1.0 = 2.0 mineral richness.
