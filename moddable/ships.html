Ships, modules and designs

The ship half of the game: hull slot grids, modules, weapons, saved designs and the roles the AI builds.

families: 6files: 1,778 tags: 264generated from: ef406fa04

A ship is assembled at load from four kinds of file: the hull gives the slot grid and the model, each module gives cost, mass, health, power, shields and thrust, the weapon file gives damage, range and cadence, and the design records which module UID sits in which cell. The shipyard's offence, defence, power and speed are sums and formulas over those files, never fields in the design. That is why copying a design file without its hull or modules produces a ship that is missing parts rather than an error.

Level 3 — how this section works

Slot letters are positional: a module's Restrictions must overlap the letter in the cell, with xI/xO/xIO requiring an exact match. A design's Modules count must equal its ModuleUIDs lines, and its Size and GridCenter must equal the hull's grid and C cell, or the design is dropped. Module and weapon UIDs come from file stems, and a weapon UID no file defines leaves the mount inert with a log line. Every hull needs a tech in its unlock closure or no design using it can ever be built.

The derived numbers are documented in ship-content-reference.md: module cost and mass sum directly, health is scaled by modifiers, speed comes from thrust against mass with a hull floor, and a design's research price is the closure of the techs that unlock its hull and modules.

HullsTier 1125 files
The chassis of a ship: a grid of slots and a model, with no weapons or engines of its own.

.hull (line based) · ShipHull.Load → ResourceManager.LoadHulls

A hull decides how many cells a design has, what may go in each, and how the ship looks. The slot grid is the real content; the rest is presentation and gating.

Level 3 — the detail

Key=value lines, then one slot row per grid row. Unknown keys are skipped without a warning. Size must equal the grid, and the C cell is the grid centre the design file also names.

Override: Files unify by file name. A mod hull named Battleship.hull replaces vanilla's wherever it sits.

  • slotsgrid Rows of slot letters.
    One string per row, no key.
    Level 3 — the detail

    One line per grid row, one character per cell, with no key: I is interior, O is outer, E is engine, and a combined letter accepts either. The C character marks the grid centre that a design stores in GridCenter, and x-prefixed slots require an exact module restriction match. A row that is one character short shifts every cell after it, which is why a design can look correct and still place modules in the wrong cells.

Ship modulesTier 1199 files
The parts you bolt into a hull: armour, reactors, shields, guns, engines, hangars and bays.

XML · ResourceManager.LoadShipModules → ShipModule_XMLTemplate → ShipModuleFlyweight

Every number a design shows is summed from these files: cost, mass, health, power, shields, thrust. The module's own file names a weapon but does not contain its damage.

Level 3 — the detail

Unknown elements are dropped silently. The UID element inside the file is overwritten by the file registry, so keep the stem and the UID equal. ModuleType is a label; ShipModule.Is() reclassifies armour, plants, engines and bays.

Override: XML unifies by file name, so the file stem is the module UID. A mod file with the same stem replaces the vanilla module.
