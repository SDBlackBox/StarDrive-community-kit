Tech tree and research

The research tree: what each node costs, what it unlocks, and the weights that make some areas cheaper for a race.

families: 3files: 192 tags: 88generated from: ef406fa04

Techs are the only gate on content. A hull, module, building or troop that no tech lists still exists in memory and simply never appears in a build list, with no error to explain why. The node's Cost is its own price; the price shown on a design is the closure of every tech that unlocks its hull and modules. Research weights multiply that cost per race and per category.

Level 3 — how this section works

LeadsTo fills the children's Parents in reverse, so a branch that nothing leads to is unreachable and silent. Unlock entries are child elements naming a UID; a UID that does not exist is at best a log line. Research.yaml is keyed by race portrait and multiplies Cost by technology type, hull class and weapon tag, with 1 neutral and 0.5 half price. MilitaryResearchStrategy sets which branch the AI walks; a path with no techs leaves it with no plan.

Unlock closure: start at a hull, walk every tech whose HullsUnlocked names it, then every parent those techs list in LeadsTo, and stop at the roots. If the walk reaches no root, the hull is unbuildable even though it loads. The same test applies to a module, building or troop.

  • UIDstring The tech's own id.
    It is the node's id for LeadsTo and every unlock list; a second UID inside LeadsTo names a child tech, not another id for this node.
    Level 3 — the detail

    The first `<UID>` in a tech file is the node's id; a `<UID>` inside `<LeadsTo><LeadsToTech>` names a child, which is why one file can show two values for this tag. Renaming the node without updating the files that lead to it breaks the branch silently, because LeadsTo is resolved by string. By convention the id matches the file stem, so an override at the same path replaces the same node; a different stem adds a second tech with the same id.

  • MaxLevelint Levels the tech can be researched.
    A tech at level N can be researched N times, each level costing more through MultiLevelCostMultiplier. Most vanilla techs are level 1; the multi-level ones are the exception.

    Allowed range: no loader bound; 0 or less makes the tech unpurchasable. Math: the first level costs Cost, each later level multiplies by 1.4 by default; 1 = one purchase, 5 = five levels.

    Level 3 — the detail

    `MaxLevel` caps repeat research, and `TechEntry` prices each later level with `MultiLevelCostMultiplier`, whose default is 1.4. Bonus effects can scale with the level, so a level-5 tech is not just five times the price but a stronger effect. Vanilla mostly uses 1, with Refining Efficiency and a few others at 5; 0 or a negative value leaves the tech with no purchasable level, so keep it at 1 or more.
