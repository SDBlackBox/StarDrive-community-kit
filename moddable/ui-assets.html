UI modding and assets

The look and the words: UI layouts, the main menu, text ids, fonts, textures, models, audio and the compiled assets that must exist.

families: 14files: 3,425 tags: 139generated from: ef406fa04

UI is a tree of elements in YAML, hot-reloadable while the game runs. Code finds controls by id, so a renamed button still draws but stops doing anything. Assets replace by relative path and a missing texture degrades to a red placeholder, while fonts and compiled shaders fail when they are missing. The main menu is the clearest worked example because every top-level option is a named element bound to a screen.

Level 3 — how this section works

MainMenus.yaml picks a layout and a 3D scene; the layout's List named buttons holds new_game, load_game, options, mods, sandbox, info, support and exit, and MainMenuScreen binds each id to a screen. 'Mods' opens the manager, and the download/update address comes from Globals URL and DownloadSite, so a total conversion can point at its own host without touching UI code. Positions are virtual pixels under VirtualSize and AbsSize 0 auto-fits the texture. Fonts, the compiled Simple/MeshLighting/SkinnedEffect/BeamFX/Distort shaders, and Content.mgcb are the static group: they do not fall back.

  • VirtualSizeint,int Virtual resolution.
    Level 3 — the detail

    The coordinate system for the whole layout: every AbsPos and AbsSize in the file is measured against it. The engine scales those virtual pixels to the real window, so a 1920x1080 layout works at 2560x1440 without new numbers. Different aspect ratios are repositioned by the alignment fields, not by rewriting the layout.
